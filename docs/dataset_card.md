# Dataset card: `data/itsm_incidents_2024_public.csv`

Anonymized incident tickets used in *IT Service Desk Automation Using ML and LLM* (revision of
AIEng-26010199). Generated by `python -m itsm.export_dataset` (anonymized file used in the experiments) followed by a
pseudonymization of organization identifiers for public release (see below). The SHA-256 of the released
file is recorded in `results/summary/phase1_v2/public_release.json`.

## Source
- Service desk of a multi-brand restaurant chain in Peru, tickets opened 2024-01-01 to 2024-10-15
  (export of 76,659 tickets).
- Kept: `Tipo = Incidente` with a non-empty title after cleaning: **59,860 incidents**.
- Language: Spanish (Peru), informal and template-heavy; median title length 2 to 3 content words.

## Fields
| Column | Description |
|---|---|
| `tid` | Pseudonymous id 1..59,860 (in order of the original ticket id; the map stays private) |
| `title_bert` | Anonymized title in its original form (case, accents, punctuation). Input for BERT |
| `title_clean` | Anonymized title after cleaning (lowercase, no accents, stop words and channel phrases removed, plurals folded). Input for TF-IDF models; also defines "same title" for the unseen-title metric |
| `category_id` | Static category 0-9 |
| `category_en` / `category_es` | Category name in English (paper) and Spanish (interface) |
| `resolver_group` | Human-assigned resolver group (`Grupo Asignado`), for the routing experiment |
| `split_seed0` ... `split_seed4` | `train` / `val` / `test` (70/10/20, stratified by category) for each seed |

No other field of the source system is included (no dates, requesters, technicians, stores,
priorities, solutions or free-text notes).

## Categories
K-means (k = 10) on TF-IDF/LSA vectors of title + solution text (`results/summary/phase1_v1/`).
Names written manually by the service desk lead from AI-drafted proposals and the evidence per
cluster (top terms, dominant human fields, 20 example tickets); definitions in
`configs/categories.yaml`. Categories 1, 3 and 9 are automated monitoring alerts (application
restarts by the NOC); category 0 is a catch-all (37.9%).

## Anonymization
1. URLs and e-mail addresses removed.
2. Person, requester and store names replaced by `XXX` (1,642 name tokens taken from the
   requester, writer and technician fields, minus IT vocabulary such as *pixel*, *delivery*).
3. Every digit run replaced by `0` (store codes, cash registers, dates, phone numbers); the
   store-name slot after a store code is masked (`ImpPixel MA0-XXX-Caja0`).
4. Any word occurring in fewer than 5 tickets replaced by `XXX` (`title_bert`) or dropped
   (`title_clean`).
38% of `title_bert` values contain at least one mask; 133 `title_clean` values are empty after
masking (kept, so the ticket population and splits are unchanged).

## Intended use and limits
- Benchmark for short-text incident categorization in Spanish; reproduces the paper's tables.
- Labels are cluster assignments (pseudo-labels), not human annotations; label noise was
  estimated by an analyst audit of 300 tickets [result pending].
- Templated alerts make some categories easy; report the unseen-title metric alongside accuracy.

## Public-release pseudonymization
Before release, words identifying the organization (company and group names, and the brand codes that
prefix store identifiers) were replaced by neutral codes (`ORG`, `GRUPO`, `MA`..`MF`) with a one-to-one
word substitution; the mapping is not released. Word-level features (TF-IDF on `title_clean`) are
unchanged up to renaming; character n-grams and transformer inputs change slightly, so re-running the
models on this file reproduces the paper's results up to small differences for those models.
